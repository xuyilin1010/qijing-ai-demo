# 公众号 SVG 导入故障研究

日期：2026-09-20。范围：无品牌旅行作品《循光而行》。状态：已定位失败症状、完成机制研究和部分实测，尚未通过公众号保存后的真机验收。

## 用户截图说明了什么

普通 img 显示星空，SVG image 的区域没有图片，SVG 圆形显示但点击不变色。这证明该次导入后的正文没有保留可用的完整图片与事件链。截图无法区分损失发生在浏览器剪贴板、编辑器粘贴清洗、草稿保存转换还是客户端处理阶段。不能据此断言“公众号不支持 SVG”，也不能只归因于网络慢。

旧版另有自己的实现问题：文字颜色依赖根节点继承，包装后部分文字变黑；把独立直立图文滚动测试接在旋转正文后，导致底部不一致；大画布默认已占满长文高度，封面揭开没有真正展开文章高度。后两项在候选版重新组织，文字已显式指定颜色。

## 编辑器实际采用的导入流程

135 官方教程提供：将 SVG 源码放入 HTML 编辑模式，再使用保存同步进入公众号草稿，并明确提醒复杂 SVG 普通复制粘贴容易出问题。[官方 SVG 导入与同步说明](https://www.135editor.com/books/chapter/1/1330)

其插件说明另提供同一浏览器中的插件同步，说明普通复制使用可能丢失 SVG 效果。授权同步与插件同步是不同路径。[官方插件同步说明](https://www.135editor.com/essences/9669.html)

Chrome 文档说明剪贴板读写可能包含 HTML 处理，提供 unsanitized 读取选项。该文档说明的是浏览器接口，并不能单独证明本次公众号失败的具体环节。[Chrome Clipboard 文档](https://developer.chrome.com/docs/web-platform/unsanitized-html-async-clipboard)

## 本次已经实测

1. 建立独立的 clipboard-lab.html，原始样本普通图片、SVG image、SVG CSS 背景均显示；两种复制入口都返回完成。但当前浏览器控制使用虚拟剪贴板，粘贴返回“virtual clipboard has no data to paste”，网页读取也没有返回结果。因此剪贴板清洗环节仍未取证，不能当作已证实根因。
2. 实际进入 135 编辑器公开页面，在空白文章中打开源码模式，导入自己生成的候选正文，切换可视模式再切回源码。回读保留 11 个 SVG、40 个动画标签、7 个 foreignObject 和两个直接 begin="click" 事件。编辑器添加了部分样式、改变了属性大小写，源码并非字节不变。回读文件保存在工作区 work/135-source-roundtrip.html。
3. 无脚本预览页设置 CSP script-src 'none'，实际脚本数 0。390×844 窗口中，封面点击后高度归零、占位由约 715px 逐渐增长至约 2498px；景观与星空图片显示，主页面未横向溢出。页宽因桌面滚动条变为 375px。
4. 实际点击看山→看水→看天空→看山，每次仅目标风景可见；星空点亮→重置→再次点亮分别为 visible→hidden→visible；短笺打开/关闭分别为 visible/hidden。
5. 候选版初次测试发现：CSS 背景直接放在嵌套 SVG 中不绘制。已改为 foreignObject 中建立 CSS 布局盒，再承载背景，并重新截图确认图片显示。没有将此问题误报为公众号过滤。
6. 图文滚动区在禁用脚本的页面中接受原生键盘翻页，scrollTop 为 0→530→1060→530，截图依次显示第一、第二、第三、第二张图文。此项证明原生滚动与吸附正常，不代表已测手机触摸。
7. 点击 135 编辑器“保存同步”后实际出现“登录您的账户 / 微信扫码注册登录”，当前会话未登录，未保存或同步公众号草稿。

源码节点保留不等于公众号保存通过；桌面移动尺寸测试也不等于微信真机测试。

## 编辑器导出后的补充验证

本轮不只数动画标签，还把 135 导出的完整源码重新放入禁用脚本的浏览器页面运行。导出通过源码编辑区的全选、复制取得；代码编辑器底层 textarea 的 value 只是输入缓冲，不能作为完整导出。

发现并修复一个实际的结构错误：把 style 放进 SVG 时，135 的 HTML 规范化会把它移到外层，之后的路线 path/circle 落入 HTML 命名空间。它们的 CSS 动画数值虽然变化，图形却不会绘制。现在样式放在 SVG 之前的 HTML 容器中；再次导入、导出后，三个路线节点都保持 SVG 命名空间，尺寸非零，截图能看见金色光点和线条。

实际导出保留 11 个 SVG、40 个动画标签、7 个 foreignObject、1 个样式表和 2 个关键帧。完整回读文件为 work/135-source-roundtrip-v2-follow-fixed.html；可运行副本为 research/135-roundtrip-preview.html。后者前置 400px、后置 800px 内容，用于验证路线进度只计算长卷本身。

修复版本 8ceddba，浏览器窗口实际为 390×844，脚本数为 0：

- 封面高度由约 687px 展开为约 2498px，封面本体高度归零。
- 页面 scrollY=0 时进度 0%；scrollY=996 时进度 36.0391%，与长卷几何计算的 36.0391% 一致。
- scrollY=2020 时进度 97.9586%；移到文章之后的 scrollY=2854 时保持 100%；返回开头恢复 0%。
- “看水”切换后仅水的场景可见；点亮星空后星座 visible，重置后 hidden。
- 编辑器导出后的三张卡片仍可原生翻页，前两次 PageDown 得到 scrollTop=530、1060。手机触摸尚未测试。

实现依据：[Chrome 滚动驱动动画](https://developer.chrome.com/docs/css-ui/scroll-driven-animations)、[MDN timeline range 定义](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll-driven_animations/Timeline_range_names)。使用文章自己的 contain 范围避免页头、页尾干扰；这两个资料并不提供公众号兼容性保证。

另核查本地参考 002：10 个 GIF 素材各有 24–113 帧，并有一个真实视频号组件；正文没有脚本、scroll/view timeline 或 sticky 声明。因此参考中一部分动态是 GIF，一部分为 SVG 事件动画，不能推断它包含真正按阅读进度计算的路线动画。
